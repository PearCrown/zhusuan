# 第13组：备份与隔离恢复

本工具通过PostgreSQL pg_dump/pg_restore做逻辑备份与恢复，不复制本机数据库目录，不建立公共管理接口。支持当前配置中的本地或云端PostgreSQL；工具需要部署环境安装与数据库兼容的可信PostgreSQL客户端。默认先从PATH找工具，Windows开发环境可使用.local中的已安装工具；--pg-bin可指定可信客户端目录。云端实际TLS和客户端版本仍须实测。

## 备份

在项目环境运行：

```powershell
.\.venv\Scripts\python.exe -X utf8 manage.py backup_database --output backups/platform-20261028.dump
```

备份当前settings配置的完整业务库，产生自定义格式.dump及.dump.manifest.json（SHA-256、大小、时间）。文件名建议每次唯一；任何同名文件已存在就拒绝覆盖。pg_dump提供数据库一致快照；不能据此声称跨外部消息服务或静态资源的一致备份。归档包含账号密码摘要、联系方式、会话、存档、成绩及审计，属于敏感资料，不可上传GitHub、公共网盘或群聊。

文件使用独占创建，POSIX模式请求0600、新目录请求0700；Windows仍以目录ACL为准，部署人员须限制读取权限。工具不提供加密、异地复制、备份轮换或密钥托管；正式服务器需补这些措施。密钥与环境配置不在数据库归档内，须另外安全保管。

失败会移除本轮创建的不完整输出，不会删除预先存在的文件。底层工具错误只给通用提示，不回显stderr或密码。密码通过子进程环境传递，不放命令参数；同机有进程检查权限的管理员仍属于信任边界。运行日志不得转储环境变量。

## 隔离恢复

仅从自己生成并可信保管的归档恢复；SHA校验能发现损坏，不能证明归档来源可信，不能阻止恶意归档内SQL。先由数据库维护人员新建空数据库与独立普通所有者，不能使用超级用户、CREATEDB/CREATEROLE角色。源/目标都在当前配置的数据库服务器；跨服务器迁移时，在新服务器环境设置连接及CA，并为恢复选择一个不同于配置DB_NAME的全新目标名称，恢复后验证再切换DB_NAME/DB_USER。工具不自动创建、删除数据库，也不覆盖当前配置库。

通过受限环境设置目标密码变量（例如RESTORE_TARGET_PASSWORD），不要把真实密码写进下列命令或Git文件：

```powershell
.\.venv\Scripts\python.exe -X utf8 manage.py restore_database --source backups/platform-20261028.dump --target-database huaxia_restored --target-user huaxia_restore_owner --target-password-env RESTORE_TARGET_PASSWORD --confirm-target huaxia_restored
```

- 数据库/角色名当前限定小写字母开头，后跟小写字母数字下划线，最多63位；不接受连接字符串。
- 目标必须与当前配置库不同、使用独立账号，确认名称必须完全一致。先校验归档SHA/大小，再连接目标，核对普通角色、所有权及空库；已有表、序列、视图、函数、自定义类型/模式或扩展都拒绝。public及系统对象不算业务内容。
- 同一目标的本工具恢复使用咨询锁拒绝并发恢复；不阻止其他SQL客户端写入，因此只能向隔离、尚未接入应用的空库恢复。不能把咨询锁当成停机维护隔离。
- pg_restore使用单事务、遇错退出、跳过旧owner/ACL，不传clean/create。失败不应留下半套业务表；目标数据库与角色继续由维护人员保留和检查，不自动删库重试。
- 读取同一个打开的归档句柄完成校验和恢复，避免校验后路径被替换；仍须保护归档与目录。底层工具限时600秒，仅用于当前规模原型，大数据量需评估执行窗口。

## 验证与切换

恢复后使用目标配置执行check_db、migrate --check和实际登录/游戏/教师范围验收，确认版本及题库与备份一致，再决定是否切换应用；不要直接让应用指向未验证恢复库。恢复本身不自动升级schema，后续升级应按增量迁移计划操作。迁移配置/数据库前先停止写入或制定切换窗口；原库继续保留，回滚也要考虑切换后新增数据。

Cookie会话需要相同站点与密钥才可能继续有效，换域名仍需重新登录。换密钥会使旧会话和未完成凭据失效，不影响密码摘要本身或固定用户ID。不能只拷贝代码就认为数据库、环境密钥及题库都已迁移。
