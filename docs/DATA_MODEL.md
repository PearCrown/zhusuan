# 用户、班级与角色基础

本文记录数据结构、校验和角色初始化。当前本地第1—7组已实现账号、教师授权名单及受限维护；访问规则见TEACHER_ACCESS.md与MAINTENANCE.md。

## 用户身份

- `accounts.User` 基于 Django AbstractUser，`id` 为 UUID，内部稳定关联身份。以后接口可称其为 `userId`，不更改数据库主键。
- 用户名先进行 NFKC 规范化、去除首尾空白、大小写归一，再校验。3—32位，仅限英文字母、数字、下划线、点、短横线，以字母或数字开头。`Alice`、` alice `、`Ａｌｉｃｅ` 都对应 `alice`。
- 用户名允许通过受控功能修改，但不会改变UUID。用户编号不得作为客户端可修改字段；学号如需加入，另设字段。
- 显示名称支持中文，去首尾空白，1—60个字符，不接受控制/隐藏格式字符；接口输出仍必须使用框架转义，不能当HTML渲染。
- 内部用户创建方法仅在省略显示名称时默认使用用户名；显式传入空值或非文字必须失败。公开注册接口仍应要求用户填写显示名称，不能依赖内部默认值。
- 密码与会话复用Django机制；创建用户时无密码意味着不可使用密码登录。
- 普通 `create_user` / `acreate_user` 拒绝授予 `is_staff`、`is_superuser`。这不是注册接口的全部安全保障，未来接口仍必须白名单处理输入。
- 默认邮箱字段仅为未验证资料，不能据此登录、绑定合并或找回密码。第10组已建立独立VerifiedContact结构；验证绑定流程将在第11组实现，见CONTACTS.md。

用户名唯一及规范格式由PostgreSQL约束兜底，防止并发写入或绕过模型保存时产生大小写重复账号。其他输入规则仍需在服务和页面层执行。

## 班级归属

| 模型 | 作用 | 数据约束 |
| --- | --- | --- |
| Classroom | 班级本身 | UUID标识，code唯一，name和code不允许空字符串 |
| StudentEnrollment | 学生当前班级 | 一个用户最多一条当前归属；未分班用户没有此记录 |
| TeacherClassGrant | 教师可管理的班级 | 一个教师可对应多个班级，同一组合不能重复 |

- 学生当前归属与教师授权相互独立，教师也可以游玩。
- 班级编号、名称在常规保存时去首尾空白，拒绝空白名称、控制字符及超长输入；编号当前大小写敏感。批量写入或直接SQL会绕过模型校验，未来维护入口必须复用校验逻辑，不能直接批量写入未经验证的内容。
- 授权记录本身不授予教师角色。第6组已同时检查账号启用、教师角色、操作权限及启用班级范围。
- 用户/班级存在归属或授权引用时，ORM删除会被保护。一般维护应使用停用或显式撤销，不应级联删除。
- 当前归属不保存历次转班历史。若以后要求按历史班级追溯教学记录，需要新增历史记录，不可假设当前关系已经支持。

## 角色初始化

执行 `manage.py init_roles`，迁移必须先完成：

| 保留组 | 权限 |
| --- | --- |
| student | 无教师或维护权限 |
| teacher | 查看授权班级数据、导出授权班级名单与成绩；成绩接口见GAME_INTEGRATION.md |
| maintainer | 维护账号与角色、维护班级归属与教师授权 |

- 命令可重复执行，不创建用户、不改成员、不自动打开管理后台。
- 保留组的权限集合由代码管理；重跑会移除额外手动添加的权限，避免无意扩权。
- 新用户创建本身不隐式加入组；第3组注册服务会在同一事务中创建用户并分配student组。无教师权限用户仍可作为普通玩家，不能仅凭组缺失判断账号失效。
- `is_staff` 不是本项目受限维护台的准入条件；维护台独立检查maintainer组及两项维护权限。教师组不会设置此标志，第7组不开放任意Django管理站点。
- 不把全局 `has_perm` 当作班级范围检查。现有列表、名单和CSV已限定范围，未来搜索、成绩与其他详情也必须接入统一检查。
- 框架的permission缓存不能用于长期复用的用户实例来判断即时撤权；后续请求按最新数据库状态检查。

## 开发与测试隔离

第9组新增ChapterProgress：用户、固定chapter_id、schema_version、revision、JSON状态、固定题库ID/版本、可空成绩/提交时间、提交班级快照和更新时间。同用户同章节唯一；有分数必须同时已提交且0—100。允许纯剧情章节完成而不计分。用户及提交班级外键PROTECT，不以删除账号/班级清理历史；转班不改历史快照。迁移gameplay.0001/0002为增量迁移，不删除旧表。详见GAME_INTEGRATION.md。

- 开发和测试数据库使用不同普通角色，均无超级用户、建库或建角色权限。
- 两个角色不具有对方数据库的CONNECT权限。
- 测试配置要求专用 `test_huaxia_` 前缀数据库和独立账号，并强制 `--keepdb`，不克隆并行数据库。
- 不要在测试库保存真实账号；测试运行器在每轮开始前核对专用目标并清理残留数据，保持表结构；测试本身也会回滚或清理测试记录。
- 普通配置同样启用测试运行器保护；即使不用manage.py入口，也会在连接测试数据库前拒绝非隔离配置。测试连接与实际目标库必须一致。
- 已有真实账号、维护审计及基于session_revision的旧会话永久撤销；验证码和100人并发尚未验收。revision还用于账号维护旧版本冲突检测，Classroom.maintenance_version用于班级编辑冲突检测。MaintenanceEvent在维护变更同一事务追加，不记录密码。
