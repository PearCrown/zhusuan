# 第10组：联系方式与发送器基础

本组仅提供内部数据结构与发送适配接口，没有新增绑定、验证码登录、短信/邮件自动找回页面或公开接口。原有用户名登录和人工密码恢复继续使用。默认发送器disabled，未安装外部服务SDK、未发送真实消息。

## 已验证联系方式

VerifiedContact关联固定用户ID，仅保存已验证记录：kind、规范化value、verified_at。每个账号最多一个邮箱和一个手机号，同种联系方式全局唯一，不能同时属于两个账号。用户外键PROTECT。没有自动建号、合并或沿用User.email的逻辑；User.email仍是未验证字段。

normalize_contact(kind,value)执行统一规则：邮箱去首尾空白，当前仅支持ASCII地址，整个地址转小写（本产品按大小写不敏感识别邮箱），保留点号及+标签，不按邮件服务商猜测别名。手机号必须显式包含+国家码及8—15位数字，不猜国家码、不自动删除空格/短横线。这是格式校验，不证明号码真实存在或归本人。

普通save执行格式规范化、拒绝没有验证时间的记录。数据库唯一约束阻止并发抢占相同身份；数据库还有基本类型/规范格式检查。直接SQL、bulk_create、QuerySet.update不执行完整邮箱校验，可信工具应调用规范化函数，并处理数据库唯一冲突。数据库不能证明收件人身份：verified_at只是完成验证的记录，不能由客户端提供后直接视为验证成功。

本组没有可供外部调用的绑定写入服务。下一组必须先实现验证码挑战，再在事务中验证用途、目标地址、会话/账号、时效、错误次数及一次性消费，才能写入VerifiedContact。待验证目标应放在挑战记录，不能提前占用身份，也不能覆盖已验证地址。更换、解绑、停用后的恢复与审计/会话撤销须与该流程一起实现，不能仅靠更新这张表。

## 发送适配契约

accounts.messaging.CodeMessage(kind,destination,purpose,code)接收规范地址、bind/login/reset用途及六位ASCII数字代码；消息不可变，repr隐藏地址和验证码。get_sender().send(message)成功返回None，失败抛出通用DeliveryUnavailable。接口不会生成验证码、认定验证通过或返回给前端。

CONTACT_MESSAGE_BACKEND默认disabled：一律明确拒绝发送，不能假装成功。显式memory仅在DEBUG=True开发环境可用；DEBUG=False时启动配置和每次发送/读取都拒绝。持有旧sender引用也不能绕过运行时限制。未知配置拒绝，不按任意模块路径加载代码。

内存发送器只保留最近100条，可由可信开发测试调用drain()取出并清空；切换禁用或检测非法环境时清空。没有控制台/文件验证码日志、公开收件箱API或持久化。进程重启即丢失，多进程不共享；drain不是生产消息队列，也不负责验证码时效/验证。代码和目标地址即使不在repr中，也禁止将dataclass转字典或其属性写入日志。

未来接入真实邮件/短信供应商时保持send契约，在受控注册点增加适配器与独立秘密配置；补充发送超时、供应商异常脱敏、发送结果不确定、限流/冷却及重发处理。不得盲目自动重试或让开发发送器进入生产。短信/邮件费用与服务开通另行决定。

## 验收范围

专用PostgreSQL测试：规范化、重复邮箱大小写冲突、每用户每种唯一、未验证/非法输入拒绝、数据库兜底；开发消息边界、容量/清空、配置切换、旧对象生产拒绝、代码及错误脱敏。没有对外发送，没有新增浏览器交互，因此本组不新增页面验收。第9组浏览器CSV实际下载补验仍保留，100人并发及生产验收尚未完成。
